# 账本密码与可选 Access 验证

2026-10-20。依据使用者批准的两种登录方式，新增默认密码登录，保留既有 Cloudflare Access 校验。[设计与运维规则](../authentication.md)和[部署指南](../deployment.md)已同步；本记录区分最初本地验证、独立云端验收和最终生产发布；早期失败按原始结果保留。

## 已实现的边界

- SSR 和所有业务 API 共用 `verifyOwner`，Access 分支复用原验签逻辑。任意 Access 字段存在即选择 Access；不完整或失败时不回退密码。
- 默认密码来自 Worker Secret `MONI_PASSWORD`，15–128 个字符；根目录空白 `.env.example` 只声明这一项，AI、微信和内部主密钥不要求部署者逐项填写。
- 密码比较使用带独立部署密钥的 HMAC 和定时安全比较。会话令牌为 256 位随机值，D1 只存摘要和凭据指纹；Cookie 使用 HttpOnly、Secure、SameSite=Strict、无 Domain，固定有效期 30 天，绑定 origin。
- 登录轮换当前浏览器的令牌；退出撤销服务器记录；密码变更不接受旧指纹，新密码成功登录清理旧凭据会话。其他浏览器的有效会话可以单独保留。
- D1 原子限流覆盖并发，每客户端每 15 分钟最多 5 次尝试。登录／退出限制同源 JSON 和大小，远端只接受 HTTPS。缺少配置或存储故障时保持拒绝。
- 登录页使用 Base UI Form／Field／Input 和项目 Button，复用现有字标和小票助手；手机、PC、中英文、系统主题、键盘焦点、错误提示和显示／隐藏密码均有覆盖。
- `/login` 只公开 GET／HEAD 页面；其他方法仍被访问检查拒绝。重定向只接受 `/` 与 `/zh` 的站内应用地址。
- 迁移 `0018_password_auth.sql` 仅新增认证会话和限流表／索引，不写业务表。会话与限流不进入账本 JSON 备份或恢复。
- 默认关闭历史版本预览 URL，独立 preview Worker／D1／DO 的部署结构不变。没有新增外部服务或依赖。

在测试分支 `codex/dual-auth-cloud-acceptance` 上验证，功能源代码 `a862c7e`，变更见 [PR #21](https://github.com/ISheepp/Moni/pull/21)。密码实例和 Access 实例是两个独立 Worker；数据库及两个 DO 命名空间分别核对，三套实例之间均不相同。没有将生产数据库绑定给可写预览。Git 分支用于标识代码，资源隔离由实际绑定保证，参考 [Cloudflare 工作流对比](https://developers.cloudflare.com/workers/previews/compare-workflows/)。

## 生产发布与数据保护

经公开 PR 合并后，将同一功能源码同步至原私密部署副本，保留其绑定和独立文档。Cloudflare 对该提交的生产构建、迁移和部署成功，活动版本已更新；本人通过原 Access 登录访问新设置页，GET /api/auth 返回 access。

上线后与发布前私密基线逐项比较：基础设置与 AI 配置完全一致；categories、tags、entries、entryTags、refundLinks、interrupts、drafts 全部一致；旧会话、消息与运行记录保留。D1、两个 DO 命名空间及全部既有 Secret 绑定一致，0018 已应用。Access 应用与策略完整比较一致，730h 会话时长保留。自定义域名与 workers.dev 两个入口的页面、业务接口及密码入口共 6 项匿名请求均被 Access 拒绝。

微信仍连接原会话，轮询时间在发布后继续推进。三个 Worker 的历史版本 URL 均已核对关闭。原始备份、服务配置与截图仅存放在被 Git 忽略的本机私密目录，不进入公开仓库。

生产只进行读取验证，没有发送记账／确认／删账／恢复指令。远端 0018 迁移只增加独立认证表和索引；业务备份不包含它们。部署保留现有 D1、两个 DO 绑定、Worker Secrets、AI 配置、微信连接及 Access 应用和策略，Access 会话仍为 730h。

真实模型和微信通道未重新发送消息；此次变化针对浏览器登录，生产只核对原有服务配置与连接状态。真实手机硬件、Safari／Firefox及真实辅助技术未测。
