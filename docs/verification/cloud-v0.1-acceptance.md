## 第一组：资源隔离与访问保护

- 生产和预览的远端绑定逐项核对：D1 database ID、Conversation DO namespace、WechatBot DO namespace 三项均不同；预览没有引用生产 DO script。
- 预览从本人受保护的初始化页面建立 CNY／Asia Shanghai 账本。AI 空配置时先完成手动收支、备注筛选、CSV、JSON 备份，之后才配置 AI。
- 在预览使用与生产相同的记录 ID，保存不同的合成内容，重复保存仅一笔；生产原记录保持不变。
- 在预览使用与现有生产微信会话相同的 thread ID。恢复前两边活动数据集前缀同为 `initial`，DO 命名输入相同，但预览读回自己的独立历史；生产会话及微信绑定保持原样。预览没有登录微信或复制微信凭据。
- 预览建立独立 Worker 级 All traffic Access 应用和 audience，沿用仅本人的邮箱规则，应用与策略时长 730h；没有调整生产应用或组织全局规则。
- 对生产自定义域名、生产默认域名、生产实际版本预览、预览默认域名、预览实际版本地址，共五个入口，分别请求首页、设置和备份接口，15 项匿名／伪造身份请求均跳转 Access。本人登录后相应页面和接口正常读取。
- 本人 HTML 和业务接口返回 `Cache-Control: private, no-store`；HTML 有 `X-Robots-Tag: noindex, nofollow` 和 noindex meta。`robots.txt` 禁止全部抓取，`sitemap.xml` 为空 URL 集。

错误签名、issuer、AUD、非本人 subject、服务身份以及应用内全部受保护路由的拒绝，沿用本地真实 D1／DO 回归。上述云端检查没有使用另一个真实用户账号登录，不将匿名／伪造身份请求描述为真实非本人登录。

### 入账、退款与统计

- 真实模型整理两笔合成草稿：CNY 35 和 USD 20／实际结算 CNY 144，合计 CNY 179。自建类目、标签、肯德基备注及推广备注保留；展示草稿后正式账目数量不变。
- 自然语言确认后恰好新增两笔，草稿状态为 posted；重复确认及同一已受理 run 的重试没有重复入账。以权威草稿状态和实际记录断言，未把运行收据中的 `ledgerSaved` 提示位等同正式入账。
- 真实查询合成推广得到一笔 CNY 144，连续追问保留关键词并返回同一明细。草稿、确认、查询及追问均无 RUN_ERROR。恢复后用新会话版本再次真实查询，同样通过。
- USD 100 按 7.20 固定折合 CNY 720；USD 30 退款默认 CNY 216。重复请求只保存一次，全额退完精确冲回，超额退款被拒绝。
- 真实浏览器同时发出两笔 USD 60 退款请求，对同一 USD 100 消费发生 HTTP 时间重叠：一笔成功，一笔 HTTP 409，实际总退款只有 USD 60。未用顺序请求冒充并发。
- USD 0.03 按 0.5 折合 CNY 0.02；分三次退 USD 0.01，主币分配为 1／1／0 分，合计精确为 2 分。实际到账覆盖值及差额单独保留。
- 九月支出、十月退款按各自发生日列示；退款继承原标签，十月可呈负净支出。筛选合计与报表接口一致。
- 软删除的记录从正式查询消失，详情返回 404；回收站保留备注，恢复后金额和备注不变。有关联退款的消费删除被拒绝。
- 标签合并保留别名；CSV 保留中文、引号及备注，对公式开头的名称／备注添加保护。JSON 包含回收站、原币、固定折算、退款关系、标签别名及会话历史，不含模型 Key。

### 完整备份恢复与执行隔离

使用合成账本的真实云端 JSON 备份往返，包含 18 条记录（17 条正式、1 条回收站）、16 条历史消息、已入账草稿及退款关联。目标是保留每个业务字段，恢复会话版本按设计递增，以拒绝旧页面继续写入。

1. 无效分类关联的备份返回 400，当前账本不变；合法备份分批准备并封存。
2. 封存后在源数据集加入合成标记，并启动真实浏览器后台 AI 请求。观察到运行中状态后开始恢复，触发 D1 执行权撤销与真实 DO 取消。
3. 恢复锁期间写入返回 423；未保存当前账本备份时提交返回 409，缺少明确确认或备份确认返回 400。
4. 实际下载当前账本备份，响应禁止缓存，文件 SHA-256 与摘要响应头一致；保存后再明确确认切换。
5. 有效提交返回 200，激活新数据集；相同命令重放仍返回 200，不再次切换。旧 dataset 写入、旧确认及旧会话版本均返回 409。
6. 原后台请求结束为 `503 conversation_unavailable`，没有迟到写入。该结果是恢复后执行权失效的拒绝，不能记为供应商正常调用失败。
7. 对恢复后的十个业务区段逐字段深比较：categories、tags、entries、entryTags、refundLinks、conversations、messages、runs、interrupts、drafts。除会话版本按设计加一外全部一致；源数据集之后新增的合成标记没有混入目标。
8. AI 加密配置独立于业务恢复，仍可用。新版本会话真实查询成功，原有完整消息保留并追加新消息；正式账目与恢复目标一致。

这些场景通过本人 Access 保护的应用接口执行，数据库和协调对象是真实云端 D1／DO。实际 AI、报价与恢复行为分开核对，未直接修改数据库绕过应用校验。测试期间修正了验证脚本对 404、423、会话版本递增和运行收据含义的假设，没有改变产品保护规则来使断言通过。

## 生产数据保护

生产账本只执行 GET：设置、账目、服务配置状态、微信状态及完整备份。没有发送记账、确认、退款、删除或恢复请求，没有修改自动入账模式，也没有重新发布生产 Worker。

- 账目、标签、分类、退款关联、草稿及备份设置前后一致；原有会话内容和运行记录保留。生产验收中途的完整业务快照一致；结束前再次核对财务数据。
- 验收期间现有微信会话收到新的正常对话；新增消息保留，没有因“快照一致”要求回滚或覆盖使用者的新活动。
- AI 配置、账本设置、微信绑定不变，微信仍连接且轮询前进。生产当前版本和全部 binding 与开始时相同。
- 原始生产备份保存在本机忽略目录，权限 0600；真实凭据没有进入测试夹具、公开文档或业务备份。预览加密主密钥独立生成，模型凭据只在运行时从本机私密配置读取并经受保护设置接口加密保存。

## 完成边界

上述证据足以完成原 #20 的首版验收，并依使用者授权关闭 #20 及 #1。父规格正文不改写，原有历史评论不删除；后续明确批准的自动入账、自动摘要、网页配置、模型协议和微信扩展仍由各自设计与验证文档约束。
