# 消费排行与图表联动验收

2026-10-26，基于 `5679e77` 的本地改动。仅使用隔离的真实本地 D1/DO 与合成账目；未提交、推送、创建云资源或部署，未访问或写入线上账本。

## 功能与口径

- 类目、标签、单笔明细均按已确认的主币金额降序排列；单笔金额相同时再按日期、记录标识降序，分页稳定。保留原币、主币金额、日期、类目、标签和独立备注。
- 点击日、周、月柱状图时段，同步更新汇总、类目排行、标签排行和逐笔明细；趋势图保留完整范围，方便继续选择。再次点选或点击“查看整个区间”可清除选择；调整日期范围或趋势间隔也会清除旧选择。
- 汇总明确展示所选日期，图表明确展示完整日期。选中状态、排行类型和展开分组保存在地址中，刷新及从账目详情返回可恢复。手机重载或调整窗口后，横向图表自动露出已选时段。
- 类目和标签可原地展开逐笔明细；每页 10 笔，跨页名次连续。单笔详情使用 Base UI Dialog，显示完整纯文本备注，支持键盘打开、Escape 关闭和焦点恢复。
- 消费排行默认只排列支出；退款按自身发生日单独汇总，不倒改原消费期间，不将收入混入消费排行。显式筛选收入或退款时按相应金额排列。标签分组仍可重叠，不相加作为总额。
- 复用受保护的统计与账目查询，不新增数据表或迁移。排序只接受固定枚举，不接受 SQL。所选日期必须完整落在报表范围内。汇总与趋势在同一 D1 批次读取；明细核对数据集与修订号，发现账目更新时提示刷新。
- 切换条件和分页时隐藏过期结果，取消旧请求；失败保留筛选并提供重试。CSV 沿用同一金额排序，导出仍覆盖全部匹配记录。
- 手机、PC 沿用现有纸色、橙色、圆角与 Base UI 控件。中英 607 个键一致，深色主题及 320px 布局通过检查。统计不调用模型或报价服务。

## 验证证据

1. 相关接口：`reports`、`entry-query`、`chat-query`、`exports` 共 32 项通过，覆盖固定换算、同金额排序、分页、独立备注、类目/标签条件、日期选择、退款、回收站和导出。
2. 全量单元测试：13 份、60 项通过。全量本地 Workers 测试：23 份、453 项通过，1 项既有不适用能力跳过。
3. 统计浏览器场景：手机与 PC 共 8 项通过。覆盖日/周/月联动、全局降序和分页名次、展开分组、多标签、外币原值、完整备注与 HTML 文本转义、刷新/返回恢复、键盘焦点、并发数据更新提示、错误重试、中英/深色及窄屏；最终复验也覆盖汇总日期和重载后选中柱的可见性。
4. 全量浏览器首轮 96 项通过。最终 UI 调整后复验为 95 项通过、1 项原有外币退款用例失败；该失败项随后独立复测 1 次及并行重复 3 次均通过。该偶发问题未算作最终全量浏览器全绿。
5. `pnpm build`（含类型检查）、全仓 Biome、中英文检查、`git diff --check`、`pnpm check:private` 通过。未新增依赖；真实配置未进入源码、前端资源或构建产物。
6. 使用最终构建在 1440px PC、390px 手机进行视觉检查；手机无页面横向溢出，所选柱保持可见。演示数据只存在本机隔离环境中。

## 原有外币退款用例的偶发失败

`tests/e2e/foreign-refunds.spec.ts` 的 Chromium 场景在第二次确认退款后，未等到退款详情中的换算来源文字。失败时页面仍是原消费的退款表单，金额 70 USD、日期 2026-10-19、预览 CNY 504.00；网络记录没有第二次退款 POST。根因尚未确认，不能据此断言生产退款功能异常或归因为统计修改。独立复测与重复复测通过，本轮未改动退款产品代码或该用例；保留这一验证限制。
