# AI 查账分析与明细展示验收

2026-10-26。本轮承接尚未提交的统计排行和上期对比改动，修改共享查账工具、模型输入的金额展示、普通会话结果卡片和微信文字回复。没有提交、推送或部署，没有访问或修改生产账本、Access 或私密 AI／微信配置。

## 行为

- 新查询明细从每页 5 笔提高为 20 笔。20 笔以内直接列出，不再显示多余的“第 1／1 页”或“下一页”提示。超过 20 笔仍明确保留分页和网页完整明细入口，避免无限拉取或把整本账塞入模型上下文。
- 旧的已保存 5 笔结果仍可解析；继续该查询时沿用其页大小，避免升级后跳过中间账目。切换日期、条件、收支类型或结果视图会重新从第一页开始。
- 分析查询默认提供完整筛选区间的次数、均价、上期对比和分组数据。提示模型先回答总览和排行，不为分析问题自动遍历明细页面。明细和全部历史查询默认不额外计算对比，可显式请求或关闭对比。
- 类目／标签变化包含本期新增和本期没有记录的分组。发给模型的变化分组按金额变化绝对值降序排列；网页和微信分别提供增加／减少排行。
- 均价、金额差和百分比由程序计算，发给模型时金额为带币种的主单位字符串；上期金额、分组金额、原币金额也按相同规则展示。无记录均价为 `null`／“—”，上期为零标为新增，不生成无限百分比。
- 外币仍用入账时确认的固定主币金额；退款按自身发生日单独统计，不并入消费次数和消费均价。总额不依赖明细分页；多标签分组不相加为总额。
- 月份与完整自然月保留原有日历口径，刷新同一查询时保留已经展示的绝对日期与对比方式。自动入账后的报表刷新仍复用同一机制。
- 网页复用统计页的频次、均价、变化排行和 Base UI 控件；每张查询卡片使用独立的变化排行标题标识，多个结果不会发生无障碍标识冲突。没有对比的明细不显示“无法对比”提示。
- 微信增加次数、均价、两期金额与变化排行。较多明细使用精简格式；长名称与备注缩略会明确说明。消息仍限制在既有 2300 字符预算内，放不下时明确标注部分展示，不伪装为全部记录，也不把当前页遗漏记录当作下一页。
- 意图服务不可用时的既有安全降级只刷新上次明确查询的明细，不新增对比或执行记账；本轮没有增加模型调用轮次。

## 验证

- 相关日期、精确均价、模型金额展示和微信回复格式：31 项通过。包含 20 笔常规微信明细全部出现、旧结果解析、长备注、Markdown 转义、零基数、上期独有分组、均价舍入和消息长度限制。
- 相关普通会话／微信接口：182 项通过。新增对比场景核对模型看到的两期金额、均价、百分比和变化排序，单次正常查账仍是工具请求加回答共 2 次模拟模型调用；查询没有新增账目。
- 最终全量单元测试：14 份、74 项通过。最终全量本地 Workers 测试：23 份、456 项通过，1 项既有能力用例跳过。

- 最终全量浏览器测试：手机与 PC 共 98 项通过（1.9 分钟）。
- 最终构建含类型检查通过；全仓 Biome、642 个中英键的一致性检查与私密配置扫描通过。实际页面检查覆盖 1440px PC、390px 手机和 320px 窄屏，无页面横向溢出。
